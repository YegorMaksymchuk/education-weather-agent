## 2. Оновлення Makefile (тільки RAG/історія)

Додати нові цілі, не чіпаючи існуючі:

- `**make historical-build**` (назва може бути `rag-build`):
  - Створює/оновлює індекс історичних даних.
  - Команда усередині: щось на кшталт `$(VENV_PYTHON) -m weather_agent.historical.retrieval build` або конкретна функція зі `retrieval.py` (після аналізу файлу).
- `**make historical-test**` (опційно):
  - Запускає тести, що покривають історичний/RAG-шар (якщо є окремі тести чи маркери, наприклад `pytest -m historical` або тести в окремій теці).
- `**make historical-run**` (опційно):
  - Якщо є режим, у якому бот використовує historical/RAG (наприклад, через змінну середовища `PROMPT_VERSION=3` або іншу опцію), додати коротку команду, напр.: 
    - `PROMPT_VERSION=3 $(VENV_PYTHON) main.py`.

У `help` додати короткі описи нових цілей, щоб список залишався зрозумілим.

## 4. Узгодженість із CI та Docker

- Переконатися, що нові Make-цілі:
  - не ламають існуючий CI (не використовуються у workflow за замовчуванням, поки не буде окремого plan-а на інтеграцію RAG у CI);
  - коректно працюють всередині Docker-образу, якщо планується зборка індексу під час CI або при запуску контейнера (ця логіка може бути винесена в окремий крок пізніше).

На цьому етапі достатньо лише оновити README та Makefile; інтеграцію RAG у CI/CD можна робити окремим планом.
